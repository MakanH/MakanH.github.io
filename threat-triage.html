Automated Threat TriageTriage automatisé des menaces

A suspicious email goes in. A verdict comes out, with its reasons attached. Un courriel suspect entre. Un verdict en sort, avec ses raisons.

A SOAR-inspired Python pipeline for the first pass on a suspicious email. It pulls the indicators out of a raw .eml, checks them against VirusTotal and AbuseIPDB, and scores the email from 0 to 100. Every point comes with a reason, so an analyst sees the evidence and not just the total.

Un pipeline Python inspiré du SOAR pour le premier tri d’un courriel suspect. Il extrait les indicateurs d’un fichier .eml brut, les vérifie auprès de VirusTotal et d’AbuseIPDB, puis donne au courriel une note de 0 à 100. Chaque point est justifié, pour que l’analyste voie les preuves et pas seulement le total.

1.0SummaryRésumé

  • Pulls the indicators. Regex extraction of IOCs (IPs, URLs, domains, file hashes) straight from raw .eml files. Extrait les indicateurs. Extraction par regex des IOC (adresses IP, URL, domaines, empreintes de fichiers) directement à partir de fichiers .eml bruts.
  • Checks them against threat intel. VirusTotal and AbuseIPDB REST APIs, with per-indicator caching and an offline fallback. Les vérifie auprès du renseignement sur les menaces. API REST de VirusTotal et d’AbuseIPDB, avec mise en cache par indicateur et repli hors ligne.
  • Tuned, not guessed. Adjusted the scoring weights to fix a false negative: 3 of 3 phishing test emails flagged, zero false positives. Ajusté, pas deviné. Poids de pointage ajustés pour corriger un faux négatif : 3 courriels d’hameçonnage de test sur 3 signalés, aucun faux positif.
  • Tested and reportable. 36 unit tests behind a 0-100 scoring engine that writes JSON and HTML triage reports. Testé et documenté. 36 tests unitaires derrière un moteur de pointage de 0 à 100 qui produit des rapports de triage JSON et HTML.

2.0MethodMéthode

Threat-intel hits are weighted heaviest because they are the hardest evidence. The email's own red flags are weak alone and strong together, the way an analyst weighs clues that agree. Les résultats du renseignement sur les menaces pèsent le plus lourd, parce que ce sont les preuves les plus solides. Les signaux propres au courriel sont faibles seuls et forts ensemble, comme un analyste qui pèse des indices concordants.

3.0Timeline of a triage runDéroulement d’un triage

One email, four stages, in order. Un courriel, quatre étapes, dans l’ordre.

  1. Stage 1Étape 1

    ExtractExtraire

    Parse the email and pull the sender, IPs, URLs, domains, file hashes and attachment names. Private addresses are dropped as non-actionable. Analyser le courriel et en extraire l’expéditeur, les adresses IP, les URL, les domaines, les empreintes de fichiers et les noms des pièces jointes. Les adresses privées sont écartées, car elles ne mènent à aucune action.

  2. Stage 2Étape 2

    EnrichEnrichir

    Ask VirusTotal about hashes, URLs and domains, and AbuseIPDB about IP reputation. Results are cached per indicator. With no API key the stage returns "unknown" instead of failing. Interroger VirusTotal sur les empreintes, les URL et les domaines, et AbuseIPDB sur la réputation des adresses IP. Les résultats sont mis en cache par indicateur. Sans clé d’API, l’étape renvoie « inconnu » au lieu d’échouer.

  3. Stage 3Étape 3

    ScoreNoter

    Combine threat-intel hits with structural heuristics into a score from 0 to 100. Every point added is recorded with a human-readable reason. Combiner les résultats du renseignement et les heuristiques structurelles en une note de 0 à 100. Chaque point ajouté est consigné avec une raison lisible.

  4. Stage 4Étape 4

    ReportRapporter

    Write a machine-readable JSON report and a self-contained HTML one. The exit code follows the worst verdict, so the tool can slot into an automated pipeline. Écrire un rapport JSON lisible par machine et un rapport HTML autonome. Le code de sortie suit le pire verdict, pour que l’outil s’intègre à une chaîne automatisée.

5.0In the terminalDans le terminal

The same run as Exhibit 02-A, from the command line. It also works without API keys: --offline skips the network and scores the structure alone. Le même traitement que la pièce 02-A, en ligne de commande. Il fonctionne aussi sans clés d’API : --offline saute le réseau et note seulement la structure.

The exit code follows the worst verdict (2 malicious, 1 suspicious, 0 clean), so a script or a CI job can act on the result. Le code de sortie suit le pire verdict (2 pour malveillant, 1 pour suspect, 0 pour propre), pour qu’un script ou une tâche d’intégration continue puisse réagir au résultat.

6.2 A report can't be turned into an attackUn rapport ne peut pas devenir une attaque

The emails being triaged are hostile by definition, so the report must never run what they contain. Les courriels triés sont hostiles par définition : le rapport ne doit jamais exécuter ce qu’ils contiennent.

8.0FindingsConstats

  1. F-01 False negativeFaux négatif

    The first weights let a credential phish through.Les premiers poids laissaient passer un hameçonnage d’identifiants.

    A lookalike sender domain plus urgency language scored 20 out of 100: benign. Either clue alone can be innocent. Together, with a link to click, they are textbook credential phishing. Un domaine d’expéditeur sosie et un langage d’urgence donnaient 20 sur 100 : bénin. Chaque indice seul peut être innocent. Ensemble, avec un lien sur lequel cliquer, c’est un cas typique d’hameçonnage d’identifiants.

  2. F-02 ResultRésultat

    Three of three phishing samples flagged, none missed.Trois échantillons d’hameçonnage sur trois signalés, aucun manqué.

    After tuning, the samples score 50, 55 and 90. The legitimate newsletter scores 0. No false positives on the test set. Après l’ajustement, les échantillons obtiennent 50, 55 et 90. L’infolettre légitime obtient 0. Aucun faux positif sur le jeu de test.

  3. F-03 ExplainabilityExplicabilité

    A verdict nobody can justify is not actionable.Un verdict que personne ne peut justifier n’est pas exploitable.

    Every alert lists the specific reasons behind its score, so an analyst can confirm the call, escalate it or dismiss it with evidence. Chaque alerte énumère les raisons précises de sa note, pour qu’un analyste puisse confirmer la décision, la faire remonter ou l’écarter, preuves à l’appui.

9.0RemediationCorrectifs

What changed after the false negative, and the safeguards around the pipeline. Ce qui a changé après le faux négatif, et les protections autour du pipeline.

  1. R-01 DoneFait

    Doubled the lookalike-domain weight, from 10 points to 20: these domains are registered specifically to deceive. Doublé le poids du domaine sosie, de 10 à 20 points : ces domaines sont enregistrés expressément pour tromper.

  2. R-02 DoneFait

    Added a 20-point compound bonus for two or more weak signals plus a clickable link. The missed email now scores 50: suspicious. Ajouté un bonus composé de 20 points pour deux signaux faibles ou plus avec un lien cliquable. Le courriel manqué obtient maintenant 50 : suspect.

  3. R-03 DoneFait

    36 unit tests cover extraction, enrichment (mocked), scoring, reporting and the CLI, including a check that the HTML report escapes hostile content. 36 tests unitaires couvrent l’extraction, l’enrichissement (simulé), le pointage, les rapports et la ligne de commande, y compris une vérification que le rapport HTML neutralise le contenu hostile.

  4. R-04 DoneFait

    A safe test corpus: documentation IP ranges and the EICAR test hash. No real malware in the repository. Un corpus de test sans danger : des plages d’adresses IP de documentation et l’empreinte de test EICAR. Aucun vrai logiciel malveillant dans le dépôt.
